# v0.1.14 构筑与路线取舍

本轮让玩家可以围绕当前牌组选择奖励、安排补给与主动精简牌组。卡牌和怪物的基础数值没有因此重新调整；下面记录的是选择结构与规则约束，不是玩家胜率或全局平衡结论。

## 行为变化

### 奖励提供不同用途

普通战、精英和前三章 Boss 的三选一仍逐槽先抽稀有度，再从合法牌池抽具体卡牌。前两张按原算法产生；只有前两张功能相同，第三张才在本次已经抽到的同稀有度池中优先排除该功能。池中没有其他功能时保留原池，不重掷稀有度。

功能分为进攻、防御、运转：攻击牌重在输出；立即格挡、治疗和削弱攻击的技能重在防御；抽牌、资源、回收和能力牌的持续准备归为运转。混合技能中的立即防护优先，附带抽一张牌不会把防御牌算成纯运转；条件收益不覆盖无条件收益。这是粗粒度去同质处理，不给牌评强弱分，也不根据当前牌组强制送配套。

卡池数量、角色专属限制、Boss 三张本角色稀有、卡牌效果、掉落稀有度曲线和商店价格均保持。十张商店卡不应用这项筛选。奖励页增加牌组张数、攻击/技能/能力数量、已有同名牌数量和查看牌组入口；平均费用使用升级后的实际费用，诅咒计入张数但不参与平均。不显示掉落概率。

### 营火增加精简

每章可在一处营火永久移除一张牌。精简会用掉本次营火行动，因此需要与回血、升级取舍；选择牌后可以确认或返回。每章一次、四章合计最多四次，不扣金币，也不额外触发回血、锻造或商店付费移除的遗物收益。不能删掉最后一张牌。

刷新保留次数，快速 SL 回到该营火开局时一并恢复牌组和次数。进入新章重置本章机会。该机制的结构测试见 `src/test/campRefine.test.ts`，本审计脚本不重复模拟精简次数。

### 选路前可比较遭遇与后路

战斗节点在章节地图建立时确定遭遇，地图预览和实际入场读取同一身份。同层尽量避免重复遭遇，也尽量避免沿边连续遇到相同遭遇；可用池不足时允许重复，不生成非法敌群。旧存档保留已有合法身份和已经开始的战斗，补齐尚未安排的后路。

选中节点可以查看敌人阵容，以及后路最近的营火/商店距离和精英数量范围；这些查询不推进随机数、不直接进入节点。后路范围只统计能够到达本章 Boss 的路径。预览提供决策依据，不替玩家选择路线。

## 结构审计样本

脚本为 `scripts/audit-strategy.ts`，结果可完整导出 JSON。

- 地图：固定种子 `STRATEGY-MAP-0` 至 `STRATEGY-MAP-299`，每种子连续生成前三章，合计 900 张图；沿用章节之间的地图随机流。
- 奖励：四角色 × 普通/精英/Boss × 200 组，共 2400 组三选一。标准难度，楼层循环 0–64；旧算法和新算法使用相同起始奖励随机状态。
- 商店：四角色各 200 组，共 800 组十张牌，与原算法逐张比对。
- 遭遇身份、地图预览和重复读取检查不改变地图或局内随机状态；奖励对照检查稀有度序列、随机流、前两张、合法角色、重复 ID 和 Boss 限制。

“分叉”包括开局多个起点，以及任一节点的多个直接后继；不按到达频率加权。阵容按敌人 ID 的多重集合区分，不把同一组敌人的不同遭遇名字当成新阵容。同层存在不同阵容不等于该层每个节点都两两不同，也不保证玩家当前能到达该层全部节点。

第二、三章各有 6 个多个小怪选项的分叉阵容相同，这是可用遭遇池和同层节点数量下的回退结果，所有规划仍满足章节、类型和楼层要求。约 12% 的直接分叉类型与阵容相同，可能仍有不同的后续补给位置；本轮不宣称每一次分叉都已经形成不同最优策略。

2400 组的稀有度序列、抽取后的随机状态和前两张具体卡牌全部与旧算法一致。566 组第三张具体 ID 改变：筛掉同功能候选后，池的索引变化也会改变原本已经不同功能的第三张，因此该数不等于被消除的 304 组同功能奖励。全部样本没有重复牌 ID、越角色或 Boss 非专属稀有牌。

800/800 组商店的十张具体卡牌和抽取后的随机状态完全不变。完整审计为 **0 条约束失败**。

## 结论的适用范围

这些样本验证了奖励减少同功能扎堆、地图提供可比较的阵容与后路，同时维持既有随机和内容约束。功能不同不代表与当前牌组同样合适，去同质也可能提高找到有用牌的机会；本轮没有量化该收益或证明所有卡牌价值相等。

脚本不出牌、不模拟损血、金币、删牌和长期遗物成长，也没有计算通关率。既有整局机器人不会利用新的遭遇预览和营火精简；直接引用它的胜率不能评价这些决策机制。需要继续观察真实牌组是否会无脑精简、所有路线是否一律避开精英，以及不同流派是否真正会选择不同敌群和补给路线。

## 复现

```bash
npx vite-node scripts/audit-strategy.ts --output /tmp/ember-strategy-v0114.json
npx vitest run src/test/cardChoices.test.ts src/test/campRefine.test.ts
```

审计结果和 JSON 在相同内容定义下可复现；任何地图规划、随机流、角色或稀有度约束失败都会使脚本非零退出。
